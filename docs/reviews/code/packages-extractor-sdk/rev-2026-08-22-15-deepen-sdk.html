Summary

The diff implements four architectural deepening opportunities in extractor-sdk:

  1. EvidenceFactory accepts ReadonlySourceReader instead of raw sourceRoot string — closes a sandbox-escape seam.
  2. PopulationCollector — new class owning the resolve→write→count flow for populations.
  3. ExtractorRunner — new class owning the full run lifecycle (createContext, run, runDeterministic).
  4. EntitySpec narrowed from 15 fields to 3 (kind, entries, adapter) + new EntityAdapter interface.

All 3 extractors and 13 test files updated to use the new APIs. No business logic changed.

Axis A — Structural Correctness

PASS — Strict typing: No new any types introduced. EntitySpec<any>[] usage in extractors is pre-existing and unchanged. The new EntityAdapter<E> interface is fully typed.
PASS — No magic numbers or untyped data: No new literal constants introduced. Existing string constants (e.g. "creatures", "items") are pre-existing population dimension identifiers.
PASS — Minimalism: PopulationCollector and ExtractorRunner are minimal — each has one responsibility and no speculative generality. ExtractorRunner.run() is a thin delegate but provides a symmetric API alongside runDeterministic().
WARN — Middle Man (Fowler): ExtractorRunner.run() is a one-line delegate to this.extractor.run(ctx). This is a mild smell — the method adds no value over calling extractor.run() directly. However, it provides API symmetry with runDeterministic() and may grow validation/logging. Acceptable as-is.
PASS — Dead code: No unreachable branches or unused exports. createExtractorContext is re-exported from deterministic.ts for backward compatibility — it delegates to runner.ts. No dead code introduced.
PASS — Unjustified removals: The sha256File import was removed from evidence-builder.ts — justified because the function read files via readFileSync bypassing the sandbox. The resolve and readFileSync imports were also removed for the same reason. All removals are directly tied to the seam-fix goal.
PASS — Error handling: No new error handling introduced. The ReadonlySourceReader already throws on path traversal / missing files — the EvidenceFactory correctly propagates those errors by calling reader.readBytes() and reader.readText() without wrapping.
PASS — Duplicated Code: The population resolution pattern (map contracts → counts, write to output, reduce for recordCount) was duplicated across all 3 extractors. PopulationCollector.collect() correctly extracts this into one place.
PASS — Shotgun Surgery: The EntitySpec narrowing touched all 3 extractors + image-asset-adapter, but this is inherent to the interface change — each spec builder needed exactly the same mechanical nesting. The change is cohesive, not scattered.
PASS — Speculative Generality: PopulationCollector.collect() accepts an optional extraPopulations parameter. This is used by the BrogueCE extractor (for image_assets population not in the manifest). Not speculative — it has an immediate consumer.
PASS — Refused Bequest: ExtractorRunner does not inherit from anything. EntityAdapter is an interface implemented by all spec adapters — no refused bequest.
